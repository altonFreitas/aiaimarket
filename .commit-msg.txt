The Database panel said every SQL file had run, having never seen three

Settings -> Database asks the database what exists and reports which files
in supabase/ still need running. It did that by reading
information_schema.columns, so it could see tables and columns and nothing
else at all -- and three files in that folder create neither:

  stock-ledger.sql           functions and a view: the rule that
                             products.qty only ever moves through
                             stock_movements
  harden-rls.sql             drops the policies that let anyone holding the
                             public anon key insert orders and upload files
                             straight past the app
  patch-audit-hardening.sql  indexes

They were not listed as unchecked. They were not listed. With every file it
did know about present, the panel said "Every SQL file has been run" -- an
owner reading it before opening the shop has been told the database is
finished, including the file that closes the anon key's direct write access.

schema_inventory() now reports five kinds -- table, view, routine, policy,
index -- still names only, still granted to nobody. Its return type changed,
and `create or replace` cannot change a return type, so the file drops the
function first; that is what keeps it re-runnable on a database holding the
old one. Every file in supabase/ is now checked except seed.sql, which is
demo data and is named in NOT_SCHEMA_FILES rather than merely absent.

harden-rls.sql is the inverted one: it removes rather than creates, so it is
applied when the three named policies are gone.

A shop that pulls this keeps its old function until it re-runs the file, and
for the checks that need the new one the panel says NOT CHECKED, not NOT RUN
-- reading an empty result as an absence would send an owner off to re-run
files already in place, while implying they had been looked at. One file is
then outstanding, so the count has a singular of its own rather than
"1 files".

Verified against PostgreSQL 16: the new function installs, re-runs, is
refused to anon, and reports harden-rls.sql as done only after that file is
actually applied. Its real rows were fed through the reader to confirm the
SQL's column names and kind values match what the TypeScript expects -- the
two have no other point of contact, and a rename on either side type-checks
perfectly and reports an empty database.

Tests: the missing one was the reverse of the check that existed. It asked
whether every entry had a file; nothing asked whether every file had an
entry, which is exactly the shape of the gap. Five mutations confirmed the
new tests bite, including identifying stock-ledger.sql by
apply_stock_movement() -- which stock-receipt.sql and audience-restock.sql
each create their own version of, so a shop that had never run it would have
been told it had. That was a real mistake made while writing this, caught by
a test that now checks each named object is created by exactly one file.
